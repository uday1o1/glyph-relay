# Corpus protocol

`corpus_protocol_v1` is GlyphRelay's frozen generated screen-content corpus and lossless OCR measurement contract.

It exists to keep implementation tuning separate from validation and final-test evidence.

The protocol contains only generated scenes and openly licensed fonts.

It contains no desktop recordings, private window content, credentials, or restricted datasets.

## Frozen identity

The no-clobber protocol lock is [the corpus protocol manifest](../protocols/corpus_protocol_v1/manifest.lock).

Its aggregate SHA-256 is `81f95f221b3a9671e8547dfc3352a0766902e4a0a719baf5c50583049e6125dc`.

The manifest file SHA-256 is `16b4da5e01d197c8e22c292ce86e2b5763b74a1516aaf1156204546368799ca8`.

The dependency lock independently binds those values to the renderer, OCR runtime, model, and font hashes.

Changing a locked generator, renderer, truth rule, evaluator, metric, manifest, final-test pool, or seed rule requires a new protocol version and invalidates earlier results.

## Split contract

| Split | Sequences | Evaluation frames | Visible glyph instances | 8-to-10px glyph instances | Access rule |
| --- | ---: | ---: | ---: | ---: | --- |
| Development | 64 | 256 | 20,480 | 5,120 | Available for implementation and tuning |
| Validation | 64 | 256 | 20,480 | 5,120 | Manifest frozen, renderer output unopened until the Milestone 4 one-shot gate |
| Final test | At least 64 committed | Generated by the sealed rule | At least 20,000 committed | At least 5,000 committed | Concrete seeds and renderer output do not exist until the Milestone 8 one-shot gate |

Each sequence declares 240 frames at 1920x1080 and 30 frames per second for eight seconds.

Evaluation samples frames 0, 60, 120, and 180.

Development and validation each contain at least eight independent sequences from code editor, terminal, spreadsheet or table, slide or diagram, browser documentation, mixed video and text, and animated typing or scrolling strata.

Their fonts, themes, layouts, sequence identities, and seeds are disjoint.

The final-test pool adds a disjoint `svg_log_viewer` scene family and uses a third disjoint font.

The committed final-test pool intentionally contains no concrete seed.

The final root seed is `SHA256(protocol_manifest_hash || randOut)` using the first verified NIST Randomness Beacon 2.0 pulse strictly after the frozen-manifest commit time plus 24 hours.

If that exact pulse cannot be verified, the final run waits instead of substituting another pulse.

## Renderer and truth

Rendering uses Playwright 1.62.1 with Chromium 151.0.7922.34 revision 1234 inside the exact Linux amd64 image digest recorded in [renderer.lock.json](../corpus/renderer.lock.json).

The browser viewport is 1920x1080 in sRGB with a device scale factor of one.

Scene animation is driven only by the declared frame identity.

The manifests retain the source text, text-region boxes, per-glyph positions, tight visible alpha masks, theme, font, motion category, logical scale case, timestamps, and rendering lock identity.

Development scenes exercise both light and dark themes, static, slow, and rapid motion, and logical 1x and 2x scale cases.

Visible post-clipping glyph pixels form the glyph truth set.

Only declared foreground borders, icons, carets, selection outlines, diagram strokes, and control affordances form the UI truth set.

Background fills, broad panels, whitespace, photographs, embedded-video pixels, and text-container rectangles are excluded from UI truth.

Glyph truth takes precedence over UI truth.

The small-glyph subset is stored per instance and contains only tight post-clipping visible glyph masks with heights of 8, 9, or 10 source-visible pixels.

## OCR and bounded character error

Lossless OCR uses Tesseract 5.3.4 LSTM English mode with OEM 1 and page segmentation mode 7.

The exact Ubuntu runtime package closure, executable and shared-library hashes, `tessdata_fast` commit, and `eng.traineddata` hash are frozen in [ocr.lock.json](../corpus/ocr.lock.json).

Each declared text region is converted with rounded BT.709 luma, polarity normalized, enlarged four times by nearest-neighbor sampling, and surrounded by a 40-output-pixel border.

Text normalization uses Unicode NFC, LF line endings, preserved case, and no spelling correction.

Each box contributes `min(edit_distance, truth_character_count) / truth_character_count`.

Errors are aggregated within each sequence and then with equal weight across the seven declared strata.

The lossless gate requires overall bounded character error at most 0.02 and small-glyph bounded character error at most 0.05.

A failed validation or final-test lossless gate produces `INSUFFICIENT_EVIDENCE` and cannot be repaired by changing compressed-result analysis under this protocol version.

## Local verification

Verify that both frozen manifests regenerate byte for byte without creating validation pixels:

```bash
make corpus-regeneration-check
```

Build the exact Linux evaluator, render only the development samples, run all OCR boxes, and enforce both development gates:

```bash
make corpus-lossless-check
```

The accepted local development run rendered 256 frames, evaluated 512 OCR boxes, and measured 0.0 overall bounded character error and 0.0 small-glyph bounded character error.

The command refuses an existing development output directory so ordinary reruns cannot silently replace evidence.

Validation and final-test renderer directories must remain absent during these workflows.

The repository protocol check validates hashes, schema, counts, split disjointness, glyph raster integrity, small-glyph assignments, final-test nonexistence, and the sealed seed rule:

```bash
make protocol-check
```

## Boundaries

The development result proves only that the frozen evaluator is suitable for the generated lossless development samples.

It is not evidence that automatic saliency works, that compressed text is readable, or that validation and final-test gates pass.

Those claims remain gated by their designated one-shot milestones and the target GPU qualification workflow.
